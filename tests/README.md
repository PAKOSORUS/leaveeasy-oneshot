# ชุดทดสอบ LeaveEasy (ทำตามด้วย Playwright MCP / agent `tester`)

ไฟล์ในโฟลเดอร์นี้คือ **ขั้นตอนทดสอบที่รันซ้ำได้** ไม่ใช่สคริปต์อัตโนมัติ — ให้ agent `tester` (หรือคน) เปิดเบราว์เซอร์จริงแล้วทำทีละขั้น เทียบผลที่เห็นกับคอลัมน์ "คาดว่าเห็น"

เว็บที่ทดสอบ: https://leaveeasy-phakhin-nantakarn.web.app

## เทสต์ทั้ง 5 ตัว

| ไฟล์ | เรื่อง | อ้างอิงสเปก | ผลล่าสุดที่เคยรัน |
|---|---|---|---|
| `A-submit-leave.md` | employee ยื่นใบลาแล้วเห็นในรายการ (รวมรีโหลด) | US-01, US-02 | ผ่าน 9/9 |
| `B-approve.md` | manager อนุมัติแล้วสถานะเปลี่ยน | US-04, §6 | ผ่าน 8/8 (รอบที่ 3) |
| `C-empty-title.md` | เว้นหัวข้อ ระบบต้องไม่บันทึกและต้องขึ้นข้อความ | US-02 | ผ่าน 6/6 |
| `S1-unauthenticated.md` | ไม่ล็อกอินแล้วอ่านข้อมูลไม่ได้ | US-08, §0.2 | ผ่าน 4/4 |
| `S2-other-employee.md` | บัญชีที่สองเปิดใบของบัญชีแรกไม่ได้ | US-08, §2 | ผ่าน 6/6 |

## บัญชีทดสอบ (ต้องมีก่อนรัน)

| บทบาท | อีเมล | หมายเหตุ |
|---|---|---|
| employee คนที่ 1 | `le.employee01@example.com` | สมัครผ่าน `signup.html` ได้ role `employee` อัตโนมัติ |
| employee คนที่ 2 | `le.employee02@example.com` | เหมือนข้างบน (ใช้ใน S2) |
| manager | `le.manager01@example.com` | สมัครแล้ว **ต้องตั้ง `role` เป็น `manager` ที่ Firestore Console เอง** ที่ `users/<uid>` |

**รหัสผ่านไม่เก็บในไฟล์นี้** ให้ส่งให้ผู้ทดสอบตอนสั่งรัน (ห้ามเขียนรหัสผ่านลงรายงานหรือ commit)
ถ้าบัญชีถูกลบหรือรหัสไม่ตรง ล็อกอินจะขึ้น "อีเมลหรือรหัสผ่านไม่ถูกต้อง" (`auth/invalid-credential`) ให้แก้ที่ Authentication ก่อน ไม่ใช่บั๊กของระบบ

## ลำดับการรัน

1. `C` และ `S1` รันเมื่อไรก็ได้ (ไม่แก้ข้อมูล / ไม่ต้องมีใบที่มีอยู่)
2. `A` สร้างใบ `[TEST]` ใหม่ทุกรอบ จด **รหัสใบ** (id ในแถบที่อยู่ของหน้ารายละเอียด `?id=...`)
3. `B` ใช้ใบที่ `A` เพิ่งสร้าง (ต้องยังเป็น `รอพิจารณา`)
4. `S2` ใช้รหัสใบของ employee01 ใบไหนก็ได้ (เช่นใบจากข้อ 2)

## ข้อควรรู้เรื่องข้อมูลที่เทสต์ทิ้งไว้

- `A` ทิ้งใบ `[TEST]` 1 ใบต่อรอบ ใบที่ยังรอพิจารณา employee ลบเองได้ที่หน้ารายละเอียด (ปุ่มลบ มี confirm)
- `B` เปลี่ยนใบเป็น `อนุมัติ` ซึ่งเป็นสถานะปลายทาง **ลบผ่านหน้าเว็บไม่ได้** (กฎ §6) ใบจะค้างในระบบ ต้องลบเองที่ Firestore Console ถ้าต้องการเก็บกวาด
- ทุกเทสต์ต้องใช้หัวข้อขึ้นต้น `[TEST]` และข้อมูลสมมติเท่านั้น

## กติกาของผู้ทดสอบ

- ห้ามแก้โค้ดของระบบเพื่อให้เทสต์ผ่าน
- ถ้าล้ม ให้จดสิ่งที่เห็นบนหน้าจอ ข้อความ error และ console/network ตรงตัว
- เทสต์ความปลอดภัย (S1, S2) ผ่านเมื่อ **เข้าไม่ได้/อ่านไม่ได้** ถ้าอ่านข้อมูลได้จริงให้รายงานเป็นบั๊กร้ายแรงทันที และห้ามพิมพ์เนื้อหาข้อมูลลงรายงาน

## วิธีสั่งรันซ้ำ

บอก agent `tester` เช่น: "รันเทสต์ตามไฟล์ใน tests/ (ระบุตัวที่ต้องการ) บัญชี … รหัสผ่านคือ …" แล้วให้เขียนผลลง `TEST-REPORT.md`
